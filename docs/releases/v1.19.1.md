# Zanskar 1.19.1

What a day on the live gateway found, fixed. Every MySQL connection through the gateway dropped
fifteen seconds after it opened, busy or idle, and the client reconnected without a word, losing any
open transaction; it no longer does. A database session can be watched live, as a terminal can, and
the statements typed in it are command lines a reviewer can list and search. A sign-in provider that
is not answering has its button greyed out, with the reason on hover and a way to check again. A
recording retention has deleted offers no Review and no Play, and a lost recording now goes at
retention too. A host key an autoscaling instance was pinned with on first sight is checked against
the instance's console output again for its first half hour. Twelve smaller things the walk found
are fixed.
Nothing widens what a session can reach. No migration. Built with Go 1.27.4.

## Added

- **Watching a database session live.** Watch on a running database session opened a page that
  said the session had ended: the gateway refused it ("protocol cannot be shadowed") while the
  recording played fine afterwards. A database session is a client in a terminal, watched as one,
  read-only and audited like any watch. The watcher sees what the person sees; the database
  credential stays in the proxy sidecar, never in the client.
- **Database statements as command lines.** What people type in a database session is now marked
  on its recording, as for SSH: the recording's command list shows the statements, and *Find a
  command* finds them ("who ran DROP TABLE?"). The last command typed just before quitting was
  lost inside the wait for its echo, for SSH sessions too; it is recorded now. Input the remote
  did not echo, a password at a prompt, is still recorded only as *(hidden input)*.
- **Test connection on a database.** A database could not be checked before people tried it. The
  button reaches the database's port from the gateway and says whether it answered; it signs in to
  nothing and records nothing on the target.
- **Check again on the sign-in page.** A sign-in provider the gateway cannot reach has its button
  greyed out instead of a red note under it; hovering, focusing or tapping it says why, and the
  round-arrow button beside it reads the list again. Once the provider answers, its button returns
  and takes the focus. The gateway now asks a provider that is not answering every 20 seconds
  rather than every two minutes, so the check finds it back soon; the asking is still the
  gateway's own, never a visitor's.

## Changed

- **A terminated session tells the person whom to ask.** The end dialog reads "Terminated by an
  administrator. Contact your administrator." for every kind of session. The reason the
  administrator gave stays in the audit log and is never shown to the person.
- **Retention deletes lost recordings.** A recording whose session ended before it was saved
  (*Lost*) was never deleted, so it and whatever part of its file was written stayed past any
  policy. It now follows the same limits, its age counted from the session's end.
- **A recording retention deleted** shows *deleted* where Review was on Sessions, has no Review on
  Recordings, and its own page keeps the details with no Play and no downloads.
- **The Recordings filter matches what the rows show**: start, user, machine (for an autoscaling
  group, the group or the instance id), protocol, how it ended and the reason under it, and *Kept
  until*, so *deleted* lists what retention removed. It matched stored codes before: "user exit"
  found nothing where the row reads "user exit". Its placeholder says what it filters.
- **The Recordings search** says what its hits were found for ("1 match for ls") and has *Clear*;
  Esc in the box, or emptying it, puts the hits away too.
- **Autoscaling.** The gateway's own ARN no longer stands above the groups: the IAM setup of each
  group names it in the trust policy, and the page warns only when the gateway runs on AWS and
  cannot tell its identity. *Check again* in the IAM setup now detects the gateway's role again
  before reloading (it re-read the answer found at start). A host key pinned on first sight reads
  "Pinned when first seen; not checked against the instance's console output" (it read "not pinned
  yet"); the OS reads *Linux*; instance ids and zones stay on one line.
- **An autoscaling session is named by its group and instance** ("zanskar-linux-asg · i-027f…")
  in Events, Activity and search hits, as on the Sessions pages.
- **A host offers credential slots for the protocols it serves**, plus any already holding a
  credential so it can be taken off; one never probed offers all four.
- **Credentials** read as names (*SSH key*, *EC2 Instance Connect*) on the page and in every menu;
  an EC2 Instance Connect credential, which never stores a secret, no longer shows a warning.
- **Smaller.** *Recordings held* on Settings › Recording storage, with what it counts (recordings
  still being written and lost ones too, unlike the dashboard's *kept*); a recordings search in
  Events reads as a sentence with its term; a name in the policies' *Who* column no longer breaks at
  its hyphen; *Add user* and *Add group* sit at the top right like every page's action; the
  username box is not capitalised or spell-checked by a phone keyboard.

## Fixed

- **MySQL sessions dropped every connection fifteen seconds after it opened.** The relay signs in
  to the database with a library that sets a deadline on each read; the last one, fifteen seconds
  ahead, was never cleared once the relay copied the connection raw. Any query after that failed
  with `ERROR 2013 (HY000): Lost connection to MySQL server during query`, the client reconnected
  silently, and an open transaction, the database in use and session variables went with it; a
  query running longer than fifteen seconds was cut off. Not seen before because test sessions
  were short.
- **A host key pinned on an autoscaling instance's first sight was never checked again.** A new
  instance's console output is often empty when the gateway first sees it, so its key was pinned
  on trust and stayed so. The gateway now reads the console again every five minutes while such
  an instance is healthy, for its first half hour: a console listing the pinned key confirms it;
  one listing only other keys holds the instance unhealthy and is audited once, as at first sight;
  an image that never prints its keys is left pinned on trust after six reads.
- **The watch page** said a session had ended, the connection lost, when the gateway refused to
  open it; it says *Could not watch*.

## For contributors

- `internal/gateway/cmdlog` is the command log the SSH and database bridges share (it was
  `sshgw`'s); `Flush` records the lines still waiting for their echo when a session ends.
- `protocol.Tapped` is a shell or a database client: what the registry gives a tap and the watch
  handler serves as a terminal.
- The recording lifecycle declares `lost → purged`; `docs/lifecycles.md` is regenerated.
- Tests that touch `||` concatenation or a `COALESCE` over timestamps run on SQLite and Postgres.

## Upgrading from 1.19.0

Install the new package, or set `ZANSKAR_VERSION=1.19.1`, and restart. No migration runs. The first
retention sweep after the restart deletes lost recordings older than the policy, as it does finished
ones, and audits each. Autoscaling instances pinned on first sight are checked against their
console output within five minutes; the gateway's role needs `ec2:GetConsoleOutput`, which the IAM
setup's permissions policy has always listed. Live MySQL sessions open before the upgrade end with
the restart, as any session does.
