# Zanskar 1.18.8

A session whose browser vanished is noticed within a minute, not at the policy's idle timeout, and a
session left open by a failed end, or by a gateway that went away, is closed by the gateway itself,
its recording finished so retention and search take it. Esc and a click outside the *Session ended*
dialog leave the way its button does, and a recording closed by the session's own end is no longer
logged as a recording that failed. A dependency fix closes a reachable vulnerability. Nothing widens
what a session can reach. No migration. Built with Go 1.27.3.

## Changed

- **A browser that vanished is noticed within a minute.** A laptop that slept or a network that
  dropped left the session listed as open until the policy's idle timeout, because nothing told the
  gateway: its writes went into a buffer and the proxy in front kept the connection (live, 2026-11-05:
  a session still listed after the person had gone). The gateway now pings the browser every twenty
  seconds while a session runs; two pings unanswered in a row close the socket, which ends the
  session as the person leaving does. The session's row and its end event say *the browser stopped
  answering*, so an auditor can tell a browser that was lost from a person who closed the tab. A
  browser answers a ping below the page's scripts, so a tab in the background still answers.
- **A session left open is closed by the gateway.** A session's row stayed open for as long as the
  gateway ran when the write that ends it failed (live, 2026-11-05: two sessions listed as live after
  their tabs were gone), and after a crash or a kill with sessions running. At start-up the gateway
  closes every row the process before it left open, as `gateway_restart`; every minute after, it
  closes a row open for more than three minutes that it is not running, as `error` with *the gateway
  lost track of this session*. A session still being set up, an application pulling its images for
  minutes before it starts, is the gateway's and is left alone. Each end is in the audit log as the
  gateway's own event (actor *system*, as the retention sweep's are), with whose session it was and
  what became of its recording.
- **The recording a swept session left is finished.** Retention and the search of what sessions
  printed read only finished recordings, so a recording whose session was never properly ended was
  kept past its *Kept until* and never searched. The sweep now finishes it from what storage holds,
  its size and digest as the session's own close would have written them. One whose bytes storage
  no longer has is left unfinished and its loss audited as `recording.lost`, so a playback that
  cannot find it has an explanation, as before.

## Fixed

- **Esc and a click outside the *Session ended* dialog leave the way its button does.** They went to
  Targets in the session's tab, the second list that *Close tab* no longer leaves behind (live,
  2026-11-05).
- **A recording closed by the session's end is not a recording that failed.** The last read from
  guacd, or a target's last bytes, could reach the recording just after the session's end had closed
  it, and the log said *recording write failed; ending session* at error for a desktop session that
  ended as the person leaving. A closed recording is now the session ending, not a failure; any
  other write error still ends the session as an error.
- **`github.com/klauspost/compress` 1.20.2** closes GO-2026-6865, a panic on two-block frames,
  reachable from the MySQL relay through the server library it uses.

## For contributors

- `session.Sweeper` (`internal/session/sweep.go`): `Startup` and `Run`, over `Repo.EndAbandoned`,
  which returns whose rows it closed. `Repo.endRow` is the one statement that ends a session, for a
  bridge's end and the sweep's; `Repo.UnfinishedRecording` and `recording.Measure` finish what a
  swept session left. The sweep's events go through `audit.Actor{IP: "system"}.Event`, and what a
  pass closed is recorded even when a shutdown ended its context.
- `connect.Handler.Starting` says whether a session is between its row and its bridge's
  registration; `main.go` has one `live` closure, the registry plus the starting set, for the
  container reaper and the sweep alike. A session counts as starting for at most
  `containers.PullTimeout` plus five minutes.
- `watchClient` (`internal/connect/watch.go`) takes a `pinger` and returns a `*clientWatch` with
  `Stop` and `Lost`; `finish` writes `clientLostDetail` into the row of a `user_exit` the watch
  caused. Its tests run on a fake socket, judged by what the watch did after so many pings, with one
  test on a real socket whose client cannot answer; the earlier rig's 40 ms pong deadline failed
  whenever CI starved the client for two pings.
- `recording.ErrClosed` is what a write to a closed recording returns; the four bridges tell it from
  a failed write.

## Upgrading from 1.18.7

Install the new package, or set `ZANSKAR_VERSION=1.18.8`, and restart. No migration runs. At its
first start the gateway closes any session row the stopped process left open, as `gateway_restart`,
and says so in the audit log; a Sessions list that showed sessions as live after their tabs were
gone is right from then on.
