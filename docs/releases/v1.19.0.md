# Zanskar 1.19.0

Every record with a life, a session, a recording, an access request, a token, an authority's key
rotation, now says what holds of it now: the API carries a computed `state` beside the stored
`status`, the console reads it and works nothing out itself, and the twenty-three lifecycles the code
has are declared once and drawn in `docs/lifecycles.md` (ADR 0047). What the review of those
lifecycles found is fixed: an account locked out by wrong passwords read *Active*, a grant whose
window had passed stayed in *Active grants* with a Revoke button, a second authority rotation could
erase the reminder to remove the old key, an enrolled user whose password an administrator reset
stayed on the code form, and a session that revocation ended kept serving file transfer while its
recording uploaded. The isolated browser's image takes Debian's fixes for zlib and apt, and Go
1.27.4 closes a crash of the gateway's HTTP server. Nothing widens what a session can reach. No
migration. Built with Go 1.27.4.

## Added

- **`state` on every record with a lifecycle (ADR 0047).** `status` is what was set; `state` is what
  holds now, from the row and the clock. Sessions read `live` or `ended`; recordings `recording`,
  `finished`, `lost`, `purged` or `discarded`; targets and autoscaling groups `active` or
  `disabled`; a target's two certificate pins (`tls_status`, `winrm_tls_status`) `none`, `pinned` or
  `changed`, the host key's words; users `active`, `locked_out`, `disabled` or `locked`; access
  requests their status, except that an approval past its window reads `expired` before the sweeper
  writes it; API tokens `active`, `expired` or `revoked`; autoscaling instances `healthy`, `unhealthy`
  or `terminated`; the SSH authority's rotation (`rotation_state`) `none`, `prepared` or `cut_over`;
  a policy's access review (`review_state`) `never_reviewed`, `current` or `due`. Every field is
  additive; nothing a client sends changes.
- **`docs/lifecycles.md`**, generated from the declarations (`go run ./hack/gen-lifecycles`): one
  section per lifecycle with its field, its states, how the state is read off the row, a diagram of
  the moves with what makes each, the moves as a table, and what is not built or not reached. The
  twenty-three include the ten no field carries: the connect flow's phases, the sign-in's steps, the
  sign-in session, the authenticator, the restart drain, an install-settings change, the installer,
  a directory sync, a notification channel and a data-key version.
- **The OpenAPI document says what the gateway sends.** `EndReason` knows `target_deleted`, written
  since 1.9.0 and rendered by the console; `Health.status` is `ok`, `ready`, `database unavailable`
  or `migrations pending`, the words the server answers, and its readiness text no longer promises a
  guacd check; `Recording` has `purged_at` and `discarded_at` and no `view_count`; `AccessSession`
  has `recording_state` and no `has_recording`; `AsgInstance` has `host_key_source`; the restart
  drain has its `action`. A client generated from the document now accepts every response.

## Changed

- **The console reads `state` and derives nothing.** One label table (`web/src/api/states.ts`) and
  one badge carry the words for every state. The Users table says *Locked out until …* for an
  account that wrong passwords locked (it said *Active*: the lock lives in `locked_until`, the cell
  read `status`). *Active grants* lists only the grants the gateway calls approved, so a lapsed one
  leaves it the moment its window passes rather than at the next sweep, and an action refused as
  decided elsewhere reloads the list. The API tokens card no longer freezes its clock at mount. The
  Recordings page's *Kept until* says *Deleted* or *Lost*. The autoscaling instances' health column,
  the policies' review-due dot and the target's certificate alerts read the gateway's word. The
  session badge and the Watch and Terminate buttons read `state`, so an ended row with no end reason
  reads *ended*, not *live*.
- **One authority rotation at a time.** Preparing a next key while the previous rotation's old key
  still waits to be confirmed removed from targets is refused (409 `rotation_pending`, with the
  reason), and the console hides *Prepare next key* meanwhile; the next cut-over used to write over
  the reminder, and targets still trusting the first old key lost the one note that said so. Prepare,
  cut over, cancel and retire each carry the state they need in the statement itself, so two
  administrators acting at once cannot pair a prepared secret with another prepared public key.
- **A lapsed grant is not revoked.** Revoke needed only `approved`, so a grant whose window had
  passed but which the sweeper had not yet written as expired could still be revoked, and timing
  alone decided whether the row read `revoked` or `expired` and its sessions ended `policy_revoked`
  or `max_duration`. It answers 409 `conflict` now, as before, with the sentence *the access request
  is expired; only a pending or approved access request becomes revoked*; a decision refused for a
  decided request reads the same way.
- **File transfer stops when the bridge ends.** The SSH client a session's file endpoints use left
  the registry only when the terminal handler returned, after the recording was closed and uploaded,
  so a session that revocation, a changed host key or an administrator ended kept listing,
  downloading and uploading files for its owner for as long as that took, minutes on a slow bucket.
  It leaves the registry the moment the bridge returns.

## Fixed

- **The sign-in page follows the gateway after a right code.** An enrolled account whose password an
  administrator set or reset typed a correct code and stayed on the code form until a reload: the
  page's own step never read the next step the gateway reported (`/auth/me` said a password change
  was owed). What is owed next is the gateway's to say; the page moves to the password change.
- **Command line: `tls` printed only the mode.** It read the certificate's subject, issuer, hosts,
  expiry, fingerprint and source from the top of the reply, where the API puts only the mode; the
  certificate lives under `active`. Its test fixture was a hand-written flat object that hid it; the
  fixture is now the server's own struct, marshalled.
- **Command line: `asg sync` said *Synced* over a cloud-side failure.** The API answers 200 with the
  error in the body, for the console to show beside the last known state; the command now reads it
  and reports the failure in the gateway's words.
- **`target_deleted` is a declared end reason.** The registry wrote it and the console rendered it
  for two releases while the Go constants and the OpenAPI enum did not know it; a test holds every
  cancellation's reason to the declared list of twelve.
- **Go 1.27.4 closes GO-2026-6859.** A race on `MaxBytesReader`'s headers crashed net/http's HTTP/1
  server, and the console, the API and the application relay all reach it. The advisory was
  published while this release was being merged; govulncheck on `main` caught it before the tag.
- **The isolated browser's image closes three Debian advisories** the image scan found in 1.18.8's:
  CVE-2026-85091 and CVE-2026-76844 in zlib (`zlib1g`, `libminizip1t64`, fixed in
  `1.3.1-1+deb13u1`) and CVE-2026-109518 in apt (fixed in 3.0.4). The base is `debian:trixie-slim`
  at `a72b443`, and the packages come from trixie-security.

## For contributors

- `internal/states`: `New(name, states, moves...)`, `Describe`, `Check(from, to)` with an `*Error`
  that names both states, `Mermaid`, `Markdown`. A declaration is data; the SQL predicate in the
  statement stays the real guard. Each domain package has a `lifecycle.go` with its `Lifecycle` and
  one `StateOf(row, now)`, pure over the struct, filled when the row is scanned.
  `internal/states/catalog` lists them all; `cmd/zanskar/lifecycles_test.go` holds the console's label
  table, the OpenAPI enums and `docs/lifecycles.md` to the declarations and names the copy forgotten.
  The rule is in `docs/working/engineering-conventions.md` and CLAUDE.md.
- `access.Repo.missOrState` returns `ErrState` wrapping a `*states.Error`; handlers that show the
  message use `errors.AsType`. `credential.ErrRotationUnconfirmed` maps to the existing
  `rotation_pending` code.
- A policy read back and written again carries `review_state`, `reviewed_at` and `reviewed_by`; the
  write ignores them. Every other write body is unchanged; the console's bodies were already built
  field by field.
- ADR 0047 leaves four questions to the owner: an Unlock action now that lockouts are visible;
  whether the stored `locked` status goes (a migration); whether a token's `state` should reflect its
  owner's state; whether the starting phase of a session should be registered so terminate and
  revocation reach it. The review's remaining findings are listed with the ADR's working notes.
- Dependencies: the AWS SDK's patch releases, `go-jose` 4.1.9, `pgx` 5.12.0 and `modernc.org/sqlite`
  1.61.1; in the console `asciinema-player` 3.18.0 (it no longer bundles `@babel/runtime` or
  `solid-transition-group`) and `vite` 8.3.6; vitest 5.1, jsdom 31, Playwright 1.65 and oxlint 1.91
  for the tests and lint; CodeQL 4.39.3, `docker/login-action` 4.8.0 and `cosign-installer` 4.1.3
  in CI and the release. None of them closes an advisory govulncheck or Dependabot reports.

## Upgrading from 1.18.8

Install the new package, or set `ZANSKAR_VERSION=1.19.0`, and restart. No migration runs. Afterwards
the Users table may show *Locked out until …* for accounts that wrong passwords have locked, *Active
grants* no longer lists a grant whose window has passed, and an authority whose old key still waits
to be confirmed removed offers no *Prepare next key* until *Old key removed from targets* is
confirmed. API clients see new fields only; the Terraform provider needs no change.

The browser image is built on a new Debian base, so hosts download it whole, about 270 MB. To spare
the first application session the pull, pull ahead:

```
docker pull ghcr.io/albatroxxx/zanskar-browser:1.19.0
```
