# Zanskar 1.18.1

What a walk through a live 1.18.0 gateway found, fixed: a rolled-back install setting says why,
the Events page and a person's Activity speak in sentences, a decision on a request is not missed,
the console stops saying on every page that it records, and it asks the gateway less. The
security contact and its `/.well-known/security.txt` are withdrawn. Nothing widens what a session
can reach. Built with Go 1.27.3.

## Changed

- **A rolled-back install setting says why.** When a change under *Settings › Set at install*
  is rolled back because the gateway did not come back, the message now carries the service's
  last lines from the journal, read before the rollback's restart writes over them: a port the
  proxy in front still holds, a file the service cannot read. On the live gateway a switch to
  managed TLS with Caddy still on port 443 had said only that nothing answered.
- **Events in sentences.** Install-setting changes and their rollbacks, updates, restarts, image
  removal, the configuration's export and the email server now read as sentences on the Events
  page, with their failed forms, instead of the raw action ("failed to boot apply system
  gateway"). The object-type filter says *email server*, *retention policy* and *command line*.
- **A decision on a request is not missed.** The access portal's notice that a request was
  approved or denied shows for a decision of the last day until it is closed, and a closed notice
  stays closed in that browser. It showed for ten minutes and was lost on the next page.
- **A person's Activity** lists the decisions on their own requests (approved, denied, revoked)
  as something done to them, and a sign-in with a second step is one *Signed in* row, not two a
  second apart.
- **The console says less.** The *is recorded* and *is logged* notices on nearly every page go:
  the audit log records all of it as before, and people are told once, by the login banner. A
  setting's description stays only where its title does not carry it, and card leads that
  repeated their heading go. *Settings › Recordings › Search what sessions printed* is now *Index
  terminal output*; the setting is the same.
- **The console asks the gateway less.** The shell's status, update, host and command-line reads
  are kept for a minute, and the approvals count for half a minute, instead of fetched again on
  every page; any change forgets them, and a refusal is never kept.
- **Narrow windows.** The admin sidebar gives way below 900 pixels instead of 760, so a window
  around 800 pixels wide no longer scrolls sideways.
- **The keyboard.** The first Tab on any page offers *Skip to content*, past the sidebar.
- The portal's Access page says what was asked and what was granted one way: a request with
  nothing granted reads "— (asked 60)".
- *Settings › Notifications*: the email server's facts, its buttons and the channels below are
  laid out apart, before and after a server is set. The selected sidebar entry loses the bar on
  its left.

## Removed

- **The security contact** (*Settings › Sign-in › Security contact*, added in 1.15.0) and the
  `/.well-known/security.txt` it published, which the owner did not ask for. Migration 0053 forgets
  the address a gateway stored. The path now answers 404, and the API answers `404 not_found` for
  the `security.contact` setting.

## Fixed

- The site's guide and install page still told people to turn on the gateway's own Let's Encrypt
  certificate, withdrawn in 1.18.0; they now say to upload a certificate on the TLS certificate
  card, or leave it to a proxy in front. The site's screenshots are retaken at 1.18.1.
- The Terraform provider's `engine` attribute no longer offers `mssql`, which the gateway refuses;
  it says `postgres`, `mysql` and `mariadb`.

## For contributors

- `docs/working/` holds how the project works: how decisions are made and recorded, how work is
  batched and released, the quality gate, how the console speaks, the security rules every change
  keeps, the documentation rules, the engineering conventions and where things live.
  `CONTRIBUTING.md` points at it.
- `hack/verify-release.sh X.Y.Z` runs the checks a draft release passes before it is published:
  the assets, the checksums and their cosign signature, the SLSA provenance, the binary's version
  and commit, and both images on both platforms, signed, with `latest` on that version.
- ADR 0045 (Kubernetes clusters as targets) is accepted as recommended and parked: nothing of it
  is built.

## Upgrading from 1.18.0

Install the new package, or set `ZANSKAR_VERSION=1.18.1`, and restart. Migration 0053 deletes one
settings row, the stored security contact, and runs in moments; back up first as for any upgrade.
A configuration file exported from 1.18.0 imports unchanged: it never carried settings.

**The console no longer tells people on each page that sessions are recorded; the login banner
is where they are told.** A gateway whose banner is empty now says it nowhere. If yours is empty,
set *Settings › Sign-in › Login banner* (the field's example reads "All activity, including every
session, is recorded and may be reviewed") before people next sign in.

The browser image's contents are unchanged from 1.18.0; on a host with an application enrolled,
the gateway still fetches the 1.18.1 tag in the background.
