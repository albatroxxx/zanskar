# Zanskar 1.6.0

A hardening release. It ships every fix from the full security, quality and usability review of
2026-10-26 (ten medium security findings, none critical or high), bounds the two runtime settings that
decide where a stored credential is sent, makes the first web application easier to stand up,
and takes the test suites from "pins the bugs we found" to "drives the features we ship".
Read **Upgrading from 1.5.0** below: there is no migration, and the four operator-visible
changes are listed there. Built with Go 1.27.3.

## Highlights

**Withdrawn access ends the sessions it admitted**
- Revoking a grant, gating a policy behind approval, disabling a target or an autoscaling group,
  and a re-probe that finds a changed host key or certificate now end the live sessions they
  affect, with the reason recorded (`policy_revoked`, `admin_terminated`, a new `trust_lost`).
  Before, each of these refused new connections and left the open ones running. Approving a
  request re-checks the policy as it stands and caps the grant at the policy's current
  maximum.

**Sign-in hardening**
- An account that signs in through OIDC or LDAP can enrol an authenticator from a full session
  only within five minutes of signing in; later it is asked to sign in again. Confirming an
  authenticator ends the account's other sessions.
- The step-up prompt (host actions, the command line, and now two settings) closes for fifteen
  minutes after five wrong codes, audited once.
- Directory accounts get the gateway's lockout, and a directory refusal, lockout or outage is
  audited as what it was.
- The username typed into a failed sign-in is audited as a short hash, never as text.
- A new sign-in ends the session the browser held before. On HTTPS deployments the session and
  OIDC state cookies carry the `__Host-` prefix, so a sibling subdomain cannot plant one.

**The desktop bridge**
- One WebSocket message is one Guacamole instruction; a message holding more is dropped and
  logged, so the clipboard and file policy cannot be slipped past as a second instruction.
  Terminal and screen sizes are bounded before they reach the bridge; WinRM lines are capped.

**Host and operations**
- `zanskar init --force` reads the existing master key the way the service does, so a key
  written as `export ZANSKAR_MASTER_KEY=...` or with quotes is preserved, never replaced; a key
  line it cannot read is refused rather than overwritten.
- `zanskar backup` and `restore` skip symbolic links in the recordings directory, in both
  directions, with a warning that names the count, and backup says in its output that local
  recordings in the archive are in clear.
- A restart waits, up to thirty seconds, for ended sessions' bridges to finish their recording
  upload and session row before the process exits, and logs by id whatever did not. An S3 upload
  is bounded at ten minutes.
- `zanskar key rotate-master -generate` stages the new key in `<file>.next` before the rewrap,
  so a crash in between never leaves the database under a key nobody holds.
- Installing a prerelease from the console is refused before any session is drained; the
  installer takes releases only.

**Two settings stay runtime, bounded (threat model risk 7)**
- The console accepts the guacd address only on the gateway's own network (loopback or a
  private range, or a name resolving there) and the MySQL relay image only pinned by digest.
  Changing or resetting either asks for an authenticator code proved in the last five minutes.
  Every dial of guacd, for a session or for the metrics check, refuses an address outside that
  network before a packet is sent. The environment file keeps its freedom.

**Applications: easier to stand up**
- The Applications page lists the three prerequisites (apps domain, public address,
  certificate) with their state and a link to each until all are met, instead of one refusal
  per attempt. The deploy guide has a recipe for a network without DNS: public DNS for a private
  address (`sslip.io`) and a wildcard certificate from a private CA. The browser suite now opens
  an application end to end through a managed-TLS gateway on every change.

**The console**
- Tables scroll inside their card on a phone, not the page. F6 moves the keyboard from the
  terminal or the desktop to its controls. A list whose read failed shows the error alone, never
  "Loading…" beneath it. The gateway-away page carries the brand. Settings has a list of its
  sections; Logs starts at 100 lines with "Show more". A session the user closed reads "You
  closed the session."

**Documents say what the code does**
- The threat model no longer claims client-side recording encryption, per-role MFA or an admin
  unlock; it says what exists (owner-only files or server-side encryption in the bucket, one
  global MFA setting plus per-policy, a fixed fifteen-minute lock). ADR 0018 says auditors do not
  see the approvals queue; ADR 0020 records the bounded-settings decision; ADR 0032 the drain's
  grace and the prerelease refusal.

**Release engineering**
- A `v*` tag builds a release only from a commit on main whose CI run passed; a tag ruleset
  restricts who may push one. Dependabot no longer proposes Node majors for the image, so the
  Dockerfile, CI and the release build the console with the same Node.

**Tests, for the record**
- Go: repository queries run on PostgreSQL as well as SQLite in CI; password hashing runs at
  reduced cost in test binaries only; six packages prove their admin-only wiring; the fuzz
  properties bite. Console: the access decisions, host-key trust, the SSH-CA rotation, terminate,
  file transfers, the events filter and every audit sentence have tests that click them; the
  browser suite runs a second account to prove role separation, checks phone layout, and opens an
  application. Dependencies: the week's updates (AWS SDK, `modernc.org/sqlite` 1.61.0, vite
  8.3.5, the scanning actions).

## Upgrading from 1.5.0

**No migration.** Install the new package, or set `ZANSKAR_VERSION=1.6.0`, and restart.

**Four operator-visible changes**
- **Cookie names on HTTPS.** The session cookie is `__Host-zanskar_session` and the OIDC state
  cookie `__Host-zanskar_oidc` wherever cookies are Secure (TLS served, or a trusted TLS proxy).
  Anything that reads the cookie by name, a script or a SIEM parser, must use the new name.
  Plain-HTTP loopback keeps the bare names. Every signed-in browser signs in again once after
  the upgrade.
- **The guacd address and the relay image, from the console.** A guacd address set in the
  console must be loopback or private (a Compose service name such as `guacd:4822` resolves
  there and is fine); a relay image set in the console must carry `@sha256:<digest>`. Values
  already stored keep working; a stored public address will be refused the next time it is
  saved. Changing or resetting either asks for a fresh authenticator code. Values in the
  environment file are not affected.
- **Backups.** Symbolic links in the recordings directory are skipped with a warning; the
  gateway never writes any. A restore removes a link where a file goes rather than writing
  through it.
- **`init --force`** refuses to run over a `ZANSKAR_MASTER_KEY` line it cannot read, instead of
  minting a new key. Write the line as `ZANSKAR_MASTER_KEY=<base64>` (an `export ` prefix and
  quotes are fine).

**Nothing else needs a setting.** A session ended by one of the new paths shows its reason on
the user's screen and in the audit log; `trust_lost` is the one new end reason.

**API changes**: `GET /admin/applications/readiness` (new); `PUT`/`DELETE /admin/settings/{key}`
answer `403 step_up_required` for the two bounded settings and the listing marks them
`step_up`; `POST /admin/system/update/install` answers `400 prerelease_refused`; `409 not_eligible` on approving a request
whose policy no longer allows it; audit details gain `live_sessions_ended`, `username_hash` replaces
the typed username on failed sign-ins, `user.logout` gains reason `replaced`, and a new
`other_sessions_revoked` count on authenticator confirmation. The cookie names above.
