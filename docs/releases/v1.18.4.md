# Zanskar 1.18.4

What a walk through a live 1.18.3 gateway found, fixed: the dashboard's security-posture tiles open
the accounts and policies they counted, a word finds users by part of a name, and nine smaller
things the walk turned up. Nothing widens what a session can reach. No migration. Built with Go
1.27.3.

## Fixed

- **A posture tile opens what it counted.** *No authenticator yet*, *Dormant (90 days)* and
  *Administrators* opened the whole user list, and *Standing access without MFA* the whole policy
  list. Each now opens the set behind its number, with a chip saying which filter is on and
  dropping it. The list and the number come from one definition, so they cannot disagree.
- **Group names are unique without regard to case.** `QA-WALK-GROUP` could be made beside
  `qa-walk-group`, though usernames were already case-insensitive. Making or renaming a group to a
  name another has in any case is now refused (`409`). A gateway that already holds such a pair keeps
  both.
- **An access review lists only people who can connect.** A review-only auditor in a group showed
  as covered by the policy and "never used", though such an account is refused whatever a policy
  says.
- **The policy list says less that is wrong.** "1 open nothing" reads "1 opens nothing". A policy
  whose grants are all standing no longer says "standing" twice. A disabled policy's no-MFA flag is
  not red, as the dashboard already leaves it out of its count.
- **The policy editor says what to choose.** A ticked host with several protocols asks for one:
  "web-1: choose SSH or VNC", where it said "web-1 has no protocol".
- **A probed host that answered nothing** reads *none found*, not *unprobed* beside a last-probed
  time.
- **A refused address is told plainly.** "address refused: 127.0.0.1 is loopback", without the
  package's `target:` prefix.
- **The Events page says what it should.**
  - A setting's key is whole: "updated setting display.theme", not "display.".
  - An access review reads "reviewed policy x".
  - A deleted account is marked once: "deleted user alice".
  - A refused create names what was asked for and why: "failed to create target x (address
    forbidden)".

## Added

- **Search finds part of a name, closest first.** Typing `zanskar` in the Users page's new search
  box lists every account with it in the username, display name or email: an exact name first, then
  names that start with it, then those where it starts a word (after `-`, `_`, `.`, `@` or a
  space), then those that merely contain it. Several words must all be found, so `zan key` finds
  `zanskar-keykloak`. The Sessions page's username filter matches part of a name too. It is plain
  database search on SQLite and PostgreSQL, with nothing to run beside the gateway.

## For contributors

- `internal/store/search.go` is the ranked-search helper; `user.Repo.Search` and `ListPosture` use
  it, and `postureWhere` is the one definition of who a posture count covers.
- `GET /users` takes `q` and `posture`. The spec already listed `q`, `status` and `role`, but the
  handler applied none of them; `q` now works, and `status` and `role` still do not.
- Not changed, and noted for the next batch: the Events actor filter still takes a whole name
  (it resolves to one account), and host, application and database search is an unranked substring.

## Upgrading from 1.18.3

Install the new package, or set `ZANSKAR_VERSION=1.18.4`, and restart. No migration runs.

In the API, `GET /users` answers `q` and `posture` (both unpaged: up to 500 matches and no
`next_cursor`), and `POST /groups` and `PUT /groups/{id}` answer `409` for a name another group has
in another case. The browser image's contents are unchanged from 1.18.3; on a host with an
application enrolled, the gateway still fetches the 1.18.4 tag in the background.
