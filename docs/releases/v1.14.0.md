# Zanskar 1.14.0

An application can name every address it uses, an API or a sign-in page beside the page it
opens, and a person browses them all in one session. The portal shows in colour who signs a
person in. A provider's people come from the provider and nowhere else, file transfer is
offered where files can move, and Disconnect asks first. Built with Go 1.27.3.

## Added

- **Other endpoints for an application.** An application keeps its upstream, the page the
  browser opens, and may name up to 31 more addresses (an API on another host, its sign-in
  page, an admin site), each with a name. The session's browser reaches all of them and lists
  them in one bookmarks folder named after the application, and nothing else. Every address
  meets the gateway's address rules: an IP literal when it is saved, a name each time a session
  starts. A name that resolves to a forbidden address refuses the session; one that does not
  resolve leaves that address out of the session, which opens anyway and says so in its start
  event. Taking an endpoint off an application ends its open sessions. The relay beside the
  browser is now its SOCKS5 proxy, dialling for each address the place the gateway looked up
  (ADR 0037, amended).
- **Colour says who signs a person in.** On the portal's Targets page a protocol Zanskar signs
  the person in to, with a credential it holds, is green; one where they give their own login
  keeps the protocol's colour. Where a grant offers both, two buttons sit side by side, in place
  of 1.13's *as me*; a legend under the list says which is which.
- **The enrolment form fills in the group's role ARN.** Once the gateway knows the role it
  runs as, *Show IAM setup* fills *Role ARN* with the role the script creates in the gateway's
  own account (`arn:aws:iam::<account>:role/zanskar-<group>`); a group in another account
  takes that account's number, and an ARN already typed is never replaced.

## Changed

- **A provider brings its people.** *Add user* makes Zanskar's own accounts only, with a
  password; the *Signs in through an identity provider* option is gone, and the API refuses
  `password_less`. A person who signs in through a provider arrives at their first sign-in, by
  the provider's sync, or over SCIM (ADR 0035, amended). With *Create an account for each new
  person* off, the provider form says only people it pushes, or who already have an account,
  can sign in. Accounts made the old way are still linked at their first sign-in.
- **File transfer where files move.** A grant offers *File transfer (SSH, RDP)* on hosts and
  autoscaling groups only: SSH's Files panel and RDP's drive. A database or application grant
  never carried files; the gateway now clears the switch there, and a VNC or application
  session no longer shows a Files button that never became ready.
- **Disconnect asks first.** *Disconnect from web-1?* with Cancel and Disconnect, then the
  dialog saying the session ended, as before. It shows in full screen too, and on a desktop its
  keys stay with the question instead of reaching the remote machine.
- **Sync now says why, in plain words.** A provider the gateway cannot reach reads *could not
  reach keycloak.example: it did not answer in time* (or the name does not resolve, it refused
  the connection, no route, its certificate is not trusted), on the sync and on the provider's
  connection test, instead of the chain of calls it came through. The full error is in the log.
- **The Rotate dialog says Zanskar does not change the account.** Rotating a password, domain
  account or SSH key stores the new secret only; change it on the machine or in the domain
  first. The dialog now opens with that.
- **The session-ended dialog**: *Back to targets* on the right, in the primary colour;
  *Connect again* beside it, plain.
- Dependency updates (the AWS SDK group, react-router-dom, oxlint).

## Fixed

- **A grant keeps its choices when its type is only looked at.** Ticking two hosts, glancing
  at Application and coming back to Host dropped the hosts. They stay now, through any number of
  types looked at; once something is chosen in another type, the grant has moved on.
- **An application's own address is checked when it is saved.** The console sends no address
  for an application, so an IP literal upstream was only checked when a session started; every
  address of an application is checked as it is saved now.
- **A status switch keeps an application's endpoints**, since every write replaces the target.
- A test that failed about one run in a hundred (a random storage key that spelt `t1`).

## Upgrading from 1.13.0

Install the new package, or set `ZANSKAR_VERSION=1.14.0`, and restart. Migration 0040 adds one
nullable column to `targets` (`app_endpoints`) and runs in moments.

The browser image changed (its entrypoint takes the policy the gateway sends): with an
application enrolled, the gateway removes 1.13.0's browser and relay images and pulls 1.14.0's
in the background (about a 270 MB download); give the disk that room, or pull them by hand
first. A browser image pinned from before still opens an application's upstream, without its
other endpoints.

API changes: `app_endpoints` on targets; `managed_login` on `/me/targets`;
`suggested_role_arn` on the autoscaling IAM preview. `password_less` on `POST /users` is now
refused (400). `allow_file_transfer` is cleared on database and application grants, where it
had no effect.
