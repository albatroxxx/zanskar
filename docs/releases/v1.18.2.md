# Zanskar 1.18.2

What checking 1.18.1 on a live gateway found, fixed: a rolled-back install setting names its
cause in one sentence, with the service's log folded beneath it; a revoked or expired grant turns
the access portal back to *Request* without a reload; *Terminate* says it ends the session, not
the access. Nothing widens what a session can reach. Built with Go 1.27.3.

## Fixed

- **A rolled-back install setting names its cause.** 1.18.1 put the service's last journal
  lines into the message, a kilobyte of JSON log cut mid-line, which ran out of the dialog. The
  message is now one sentence, the gateway's own reason: for a port another program holds, "port
  80 is in use by another program, such as a proxy in front of the gateway". The lines sit
  beneath it, folded, under *Service log*. The helper reads only what the service logged since
  its own restart, so an earlier failed start's error is never blamed for this one. The lines
  stay out of the audit record, which keeps the sentence.
- **No notice runs past its edge.** A long word in an alert, or in a detail on the Events page,
  breaks onto the next line instead of running past the border. That includes a path, a hash or
  a line of JSON. The long message 1.18.1 wrote into the audit record of a rolled-back change
  now wraps inside its row.
- **A revoked grant turns the portal back to *Request*.** An administrator revoked a grant while
  its RDP session ran. The gateway ended the session and stopped listing the grant, but the
  person's *Targets* page still offered RDP and counted "1 grant expiring soon" until a reload:
  it read the grants once, when it opened. It now reads the grants, the open sessions and the
  pending requests again whenever it is looked at again, from another tab or another window. It
  also reads them when the soonest grant ends or starts to count as expiring soon, so a grant
  that runs out with the page open turns back to *Request* on time.

## Changed

- ***Terminate* says what it does.** The dialog said "The user's terminal closes now", even for
  a desktop session, and nothing about access. It now says the session closes and the access
  stays, with *Approvals* linked for revoking the grant. The guide says the same.
- **The docs say what an operator ran into.**
  - The install page says the switch from *proxy* to *managed* cannot be made from the console
    while the proxy is how you reach it. Make that switch on the host, with the certificate files
    in place first, because a browser that has seen the gateway's HSTS refuses its self-signed
    certificate.
  - The guide says the login banner is the one place the console tells people their sessions are
    recorded. The banner has no default text, so set it before inviting anyone.

## For contributors

- ADR 0020 and ADR 0021 record recommendations the owner parked on 2026-11-04. Nothing of them is
  built:
  - a check on the ports before an install setting restarts the gateway;
  - the sign-in notice beside the form;
  - a notice before the certificate expires;
  - the key and certificate request made on the gateway;
  - warnings when an uploaded certificate's names or chain do not fit.
- `docs/working/console-copy.md` no longer says the login banner has default text.

## Upgrading from 1.18.1

Install the new package, or set `ZANSKAR_VERSION=1.18.2`, and restart. No migration runs.

In the API, `GET /admin/settings/boot/result` gains `log`, the service's last lines when a
change did not come back. Its `message` is now the cause alone.

The browser image's contents are unchanged from 1.18.1. On a host with an application enrolled,
the gateway still fetches the 1.18.2 tag in the background.
