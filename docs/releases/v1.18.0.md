# Zanskar 1.18.0

**Under *Dependencies: Any public address*, an application session's relay now reads the
session's requests in clear, cookies and tokens included: it terminates TLS with a certificate
authority made for that session alone and verifies the real site itself. It logs the host and
the kind of each request it refuses, never a path, a header or a body. An application whose
session must not be read is set to *Its origins only*, which is unchanged.** With the relay
reading, the three limits of 1.17.0 go: a frame from a third party loads, any port works, and a
dependency on a private address is learned and allowed in one click instead of listed in
advance. Email notifications go through one mail server set once; the certificate from Let's
Encrypt is withdrawn in favour of the TLS certificate card; the dashboard loses a tile and an
icon; a denied request is announced; a person's activity is their own. Built with Go 1.27.3.

## Added

- **Frames, any port, and private addresses as dependencies** (ADR 0037, amended 2026-11-03,
  later). The relay is an HTTP proxy that inspects: a top-level page (the address bar, a link, a
  new tab, a popup) opens at the application's origins alone and gets the relay's own *This
  page is blocked* anywhere else; a frame, a script, a style, a font, an image, a fetch or a
  WebSocket is a dependency, through to any public address on any port.
- **Private dependencies.** An application's *Dependencies* gains *Private networks* (CIDRs) and
  *Private hosts* (host:port) its pages may also load from; in the API `app_private`, in the
  configuration file and the Terraform provider likewise. Taking one away ends open sessions.
- **Blocked dependencies, learned.** What a session's relay refused is read from the relay's log
  every 30 seconds and as the session ends, and kept per application. The application's page in
  the console lists it under *Blocked*, with what asked and from which page: **Allow** adds a
  private host in one click; a page someone tried to open is marked as an endpoint's business;
  a loopback, link-local or metadata address is marked as never allowed. *Clear* forgets the
  list. In the API, `GET` and `DELETE /targets/{id}/dependencies`.
- **One mail server** (ADR 0039, amended 2026-11-03, later). *Settings › Notifications › Email
  server*: the SMTP host and port (587 with STARTTLS, 465 with TLS), an account whose password
  the gateway seals, and the sender, set once, tested with one message to an address you name,
  and removed. An email channel names its recipients alone. In the API,
  `/admin/notifications/email-server` (`GET`, `PUT`, `DELETE`, `POST …/test`), audited as
  `notify.email_server.*`.
- **The TLS certificate card takes three files**, as a certificate manager does: the
  certificate, its private key and the CA's chain. *Install or replace the certificate* serves
  the new one from the next connection.
- **A denied request is announced** in the access portal as an approved one is, with the
  approver's note, for ten minutes after the decision.

## Changed

- **Dashboard.** The *Sign-in providers failing* tile goes (the notice above the tiles stays):
  *Needs attention* holds pending approvals, hosts needing attention, the day's failed sign-ins
  and the day's failed actions; *Activity* holds the open sessions, the grants running now (its
  own tile again, with how many end within the hour), the day's sessions and the day's refused
  connections. The warning icon beside the system disk's reading goes: the bar's colour says
  it.
- **A person's Activity in the access portal** lists what they did as a user (sign-ins, sessions,
  requests) and what was done to their account, not what they did as an administrator in the
  admin portal, which the Events page lists.
- The browser no longer verifies an `https` upstream itself under *Any public address*: the
  relay does, against the application's CA bundle beside the system roots. Chromium's catch-all
  block goes under that setting (it blocked frames too); the scheme blocks stay. Under *Its
  origins only* the policy is as it was.
- The relay container's memory cap is 256 MB (it terminates TLS now); the relay logs at the
  gateway's level.
- No search from an application session's address bar.

## Removed

- **The certificate from Let's Encrypt** (ADR 0021's amendment of 2026-10-30, withdrawn). The
  owner wanted one place to install and replace the gateway's certificate, which the TLS
  certificate card is. *Settings › Let's Encrypt* and the `tls.acme`, `tls.acme_email` and
  `tls.acme_directory` settings go, with the ACME client and the `acme_cache` table (migration
  0052). A certificate from an ACME CA is the business of a proxy in front of the gateway
  (`proxy` mode: Caddy, nginx), as it was before that amendment.

## Upgrading from 1.17.0

Install the new package, or set `ZANSKAR_VERSION=1.18.0`, and restart. Migrations 0049 to 0052
add two columns and a table and drop one, and run in moments. No new browser image is needed:
the relay is the gateway's own image.

- **Applications.** From the restart, every application under *Dependencies: Any public
  address* (the default) runs its sessions through the inspecting relay, which reads their
  HTTP in clear. Set *Its origins only* on any whose session must not be read. Private
  dependencies that were listed as endpoints keep working; they can move to *Private hosts* if
  they should not be bookmarks.
- **Email channels.** At its first start the gateway takes the first email channel's server,
  password included, as the mail server, and leaves every email channel with its recipients;
  the log says so. Check *Settings › Notifications › Email server* and press *Test*.
- **Let's Encrypt.** An install that had it on serves its uploaded, file or self-signed
  certificate after the restart. For a Let's Encrypt certificate, put Caddy or nginx in front
  (`ZANSKAR_TLS_MODE=proxy`), as the package install does by default.

A plain-`http` page framing a plain-`http` third party cannot be told from a navigation (the
browser sends no fetch metadata to an insecure destination) and is refused as one; list the
framed host as an endpoint.
