# Zanskar 1.18.7

A session tab closes itself when the session ends, and what upgrading a live gateway to 1.18.6
found, fixed: the dashboard's image size is right after an update, and the log keeps the Settings,
dashboard and portal page reads out of the way. Nothing widens what a session can reach. No
migration. Built with Go 1.27.3.

## Changed

- **A session tab closes when the session ends.** Each session opens in a tab of its own (ADR
  0038), and every *Back to targets* loaded a second Targets list in that tab, so two sessions left
  two windows of noise behind. A tab one of the portal's own links opened now says *Close tab* in
  the *Session ended* dialog and closes, and the browser returns to the tab you came from (which
  tab it picks is the browser's choice). The dialog still comes first, because it says why the
  session ended and offers *Connect again*. A tab that cannot be closed (a refreshed one has lost
  the history that allows it) goes to Targets as before, and a tab opened any other way (a
  bookmark, a pasted address) keeps *Back to targets*.
- **Page reads at debug.** Opening Settings wrote eight info lines (settings, notifications, the
  email server, TLS, storage, API tokens, retention), the dashboard its overview, the portal its
  targets, sessions and access. A served read of these is at debug; a change and a failure are
  still at info.

## Fixed

- **The dashboard's image size is right after an update.** *Container images* read 20.0 MB of the
  272 for as long as it was watched after the 1.18.6 update: the gateway's image is pulled first and
  the browser's nine seconds later, the first read ran between them, and only an empty read was
  tried again soon. The size is now read every twenty seconds for the first two minutes whatever
  it found, and every five minutes after that.

## For contributors

- `SessionState.from_portal` is set by the connect page when our own link was just clicked;
  `SessionEndedDialog` takes `closable`. The e2e session test clicks *Close tab* and waits for the
  tab's `close` event, which proves a real Chromium allows it (the tab's one history entry was
  replaced, not pushed).
- `imagesSettle` beside `imagesRetry` in `internal/lifecycle/metrics.go`.

## Upgrading from 1.18.6

Install the new package, or set `ZANSKAR_VERSION=1.18.7`, and restart. No migration runs. The
browser image's contents are unchanged from 1.18.6; on a host with an application enrolled, the
gateway still fetches the 1.18.7 tag in the background.
