# Zanskar 1.11.0

The dashboard on one screen, inventory first, with the gateway, its clock and how much the
audit log and the recordings take in a column beside the tiles; Ctrl+Shift+F6 instead of F6
to reach a session's controls, which on a desktop now work from the keyboard; the time zone
picked from a searchable list; identity providers that say when they last synced and when
they sync next; and a desktop that the remote machine ended says what guacd said. Built with
Go 1.27.3.

## What changed

- **The dashboard fits one screen.** Inventory comes first, then what needs attention,
  activity and security posture, four tiles a row; the gateway sits in a column on their
  right: its clock (the time, then the date and zone on one line), the gateway card with
  each gauge's name and reading on one line, and *Storage*. The two columns start and end
  level, and the gaps between rows never change: the shorter column's tiles take the
  difference. In a 1707 x 807 window, and at 1440 x 790 and 1512 x 860, nothing scrolls.
- **Storage instead of Integrity.** The Integrity row is gone from the dashboard. In its
  place, two tiles: *Audit log*, its size (estimated from the newest thousand events) and
  how many events it holds, opening Events; and *Recordings*, the exact size of the
  recordings kept and how many, opening Recordings. The integrity checks still run in the
  background and are still in `GET /api/v1/admin/overview`; the dashboard no longer shows a
  broken audit chain, a lost recording, a failing directory sync or a SIEM export falling
  behind.
- **Ctrl+Shift+F6 moves between a session and its controls**, on a terminal and on a desktop;
  F6 alone, and F6 with other modifiers, now reach the remote machine (Chromium's address bar
  in an application session, Windows programs, `mc` and `htop`). Ctrl+Alt+F6 was not taken
  because it switches the console on a Linux client. Pressed again on the controls, it goes
  back to the session.
- **A desktop's controls work from the keyboard.** Since 1.6.0 the old F6 moved focus to the
  desktop's bar, but Enter, Space and Tab still went to the remote machine, so no control
  could be pressed. Now Tab moves through the controls and Enter presses one until the
  keystroke is pressed again, the desktop is clicked or focus leaves the page. The remote
  machine sees a whole Ctrl+Shift+F6, so a Windows host does not take a bare Ctrl+Shift as
  its keyboard-layout switch. Space does not press a desktop's button; Enter does.
- **The time zone is picked from a list.** Settings, Display, Time zone opens every zone the
  browser knows, UTC included, each with its offset and name ("UTC+05:30 · Kolkata (Asia) ·
  India Standard Time"), west to east, this browser's own marked; what is typed searches the
  city, region, name, offset ("+5:30") and older names ("Calcutta"). The arrow keys, Enter
  and Escape work. Before, the field offered only the zones matching what it already held,
  which looked like nothing.
- **Identity providers say when they last synced and when they sync next** (a provider listed
  on a schedule): *Last synced* with the time, the run's result behind its icon, and *Next
  sync* with the time, *within a minute* when it is due, or *paused while disabled*.

## Fixed

- **A desktop the remote machine ended read only "target lost" to administrators.** A
  Windows RDP session ended mid-way with "Upstream error.": in guacd 1.6.0 that is a
  disconnect the RDP server sent with a reason code guacd has no words for (a dropped
  network is "Connection closed."). The session's end now carries guacd's words and status:
  Events reads *ended the RDP session on windows-host (target lost: Upstream error.)*, the
  event's details hold `detail` and `status`, and the gateway logs a warning. The
  troubleshooting page says where the real reason is: Windows' Event Viewer,
  TerminalServices-LocalSessionManager, Operational, event 40, or guacd's log at debug level.
- **The Session ended dialog** no longer tells the person whose session ended how long
  recordings are kept.

## API

- New: `storage` on `GET /api/v1/admin/overview` (`audit_log.events`,
  `audit_log.approx_bytes`, `recordings.count`, `recordings.bytes`); `next_at` on an
  identity provider's sync status (null while it is disabled or a run is going).
- Changed: a `session.end` event for a desktop that guacd ended carries `detail` (guacd's
  words, at most 200 bytes) and `status` (its Guacamole status, `0x0203`).

## Upgrading from 1.10.0

Install the new package, or set `ZANSKAR_VERSION=1.11.0`, and restart. No migration runs, so
1.10.0 starts on the same database.

The browser image's recipe (`deploy/browser`) has not changed since 1.10.0, so unless its
Debian packages have, the image reuses 1.10.0's layers and the pull is quick. To spare the
first application session even that, pull ahead:

```
docker pull ghcr.io/albatroxxx/zanskar-browser:1.11.0
docker pull ghcr.io/albatroxxx/zanskar:1.11.0
```

Anyone used to F6 for a session's controls: it is Ctrl+Shift+F6 now (on a MacBook with
Fn as well, unless the function keys are set to standard).
