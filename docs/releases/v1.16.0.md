# Zanskar 1.16.0

The rest of what the 2026-11-03 walk through a live gateway suggested, built; four eyes taken out
again. Automation signs in with an API token, and a Terraform provider manages groups, targets and
policies with one; what a terminal session printed can be searched as well as what was typed; a
request's notification opens that request, and approving it asks for a recent code; the sign-in
page says a provider is not answering before anyone tries it. Built with Go 1.27.3.

## Added

- **API tokens** (ADR 0044). *Settings › API tokens*: a token for automation, with a name and a
  life of up to a year, its secret shown once. Sent as `Authorization: Bearer zapi_...`, it is the
  administrator who made it, on the configuration API only: groups, targets and policies, read
  and written; credentials, read only; the configuration file's export and import. It cannot sign
  in to the console, open a session, reach a setting or make another token, and it stops when it
  lapses, when it is revoked, or when its owner is no longer an active administrator. Making one
  asks for a recent authenticator code. Changes made with a token are audited as its owner, the
  token named.
- **A Terraform provider** (ADR 0044), in the repository at `terraform-provider-zanskar/`:
  `zanskar_group`, `zanskar_target` (a host, a database or an application) and
  `zanskar_access_policy`, with `zanskar_credential` and `zanskar_group` data sources that find an
  id by name, so no secret is in a plan or a state. Built and installed from the repository until
  it is on the Terraform Registry (its README says how).
- **Search what sessions printed** (ADR 0041 amendment). *Recordings › Find*, *Output*: a line a
  terminal session printed, such as an error message, across every recording still kept; each hit
  names the command it followed and opens the recording at that moment. Escape codes are removed
  and a recording's first 5,000 lines are indexed. *Settings › Recordings › Search what sessions
  printed* turns it off and empties that index.
- **Approve from a notification** (ADR 0039 amendment). A request's message links to that request:
  it opens ready to approve, or says who decided it and when. The link approves nothing. Approving
  asks an approver who has an authenticator for a code from the last 5 minutes; *Settings ›
  Sign-in › Approving asks for a code* turns that off. The console command line asks for the code
  and runs the line again.
- **A provider that is not answering, said before anyone tries.** The gateway asks each enabled
  OpenID provider for its discovery document every two minutes; one that does not answer is named
  under its button on the sign-in page, which says a password account still works.
- **On the dashboard**: a *Sign-in providers failing* tile, and *Failed actions (24h)*, under
  *Needs attention*. A recordings disk 80% full offers to move the local recordings to the bucket
  in one step, or links to *Recording storage* to set one up.

## Changed

- **Admin includes auditor and user.** Ticking admin shows the other two ticked and greyed out;
  roles are kept as admin alone, and accounts holding all three keep admin.
- **A closed notice stays closed.** The dashboard's notice that a provider failed its sync, once
  closed, stays closed in that browser while the outage lasts; it shows again when more providers
  fail, after a day, or at the next outage.
- **Fewer reads.** The sidebar's Approvals count is read when it is old or a decision changes it,
  not on every page, and the Approvals page hands it the count it reads itself.
- **The log keeps no trail of addresses.** A served request's line in the gateway's log no longer
  carries the client's address; a failed one keeps it. The audit log keeps the address of every
  sign-in, connect and change.
- Checkboxes are in the console's accent colour, not the browser's blue.

## Removed

- **Four eyes** (ADR 0042, withdrawn). *Second person watches* is gone from grants: no session
  waits for a watcher. A policy saved with it keeps the setting in its stored grants, where it is
  no longer read, so its sessions start without waiting. The API refuses `require_watcher: true`
  (`400 four_eyes_removed`) and the configuration file refuses it at import, rather than drop a
  control in silence; `false` is accepted. The notification kind *A session waits for a second
  person to watch* is retired: a channel that asked for it keeps its other kinds. Watching a live
  session is unchanged.

## Fixed

- The 1.15.0 notes said twelve suggestions were built; eleven were. The twelfth, the Terraform
  provider, is in this release.

## Upgrading from 1.15.0

Install the new package, or set `ZANSKAR_VERSION=1.16.0`, and restart. Migrations 0045 to 0047
add two tables and a column and tidy roles, and run in moments; existing terminal recordings are
then read once more, in the background, for what they printed. Approvers with an authenticator are
asked for a code when they approve. In the API: `GET /access-requests/{id}`; `/admin/api-tokens`
and bearer tokens; `/recordings/search?in=output` (`409 output_not_indexed` while the setting is
off); `not_answering` on `/auth/providers`; approving can answer `403 step_up_required`; the console
command line can answer `403 cli_fresh_code_required`; `/connect` no longer answers
`watcher_unavailable` and no session ends `no_watcher`. The browser image's contents are unchanged
from 1.15.0; the gateway still fetches the 1.16.0 tag in the background.
