# Zanskar 1.12.0

Sessions, watches and recordings open in a tab of their own, so a person runs several
sessions at once and an auditor inspects several side by side
([ADR 0038](../adr/0038-sessions-and-reviews-open-in-their-own-tab.md)). Host actions can be
done now without typing 0, a recordings row offers Review alone, and the player loses its
line of keyboard instructions. Built with Go 1.27.3.

## Changed

- **A session opens in a tab of its own.** SSH, WinRM, RDP, VNC, the SQL client, an
  application's Open, "as me", and each instance in an autoscaling group's chooser open the
  session in a new tab, and the Targets list stays where it was: run several sessions at
  once. A click, a Ctrl or ⌘ click and a middle click all work. Asking for your own login
  happens in the new tab. The session's ticket still lives only in the tab that asked for
  it, never in an address.
- **A session link opened from anywhere else asks first.** A link to a session that a page
  of Zanskar did not just open (another site, a bookmark, a pasted address, the browser's
  "Open link in new tab" menu) shows the machine and a **Connect** button instead of
  connecting by itself, so no page can start a session in your name.
- **Watch and Review open in a tab of their own**, as do the recording links in Sessions and
  Events, so several live sessions or recordings can be inspected at once. Leaving a watch
  goes to the Sessions list.
- **Tabs say what they show**: `web-01 · SSH`, `Watching web-01`, `Recording · alice on
  web-01`.
- **Restart now, Reboot now, Stop now, Install now** (and *Apply and restart now*) beside the
  button that lets live sessions finish, with the same hostname and authenticator code; the
  minutes field says how many sessions are live.
- **A recordings row offers Review alone.** The recording's page has the downloads (the file,
  and the transcript for a terminal), each still an audited view.
- **No line of keyboard instructions under the recording player.** The keys still work, and
  each control's words are in its tooltip.

## Upgrading from 1.11.2

Install the new package, or set `ZANSKAR_VERSION=1.12.0`, and restart. No migration runs, and
the browser image is 1.11.2's recipe. Nothing changes for scripts: the API is the same, and
`/connect` is a page of the console, not an API route.
