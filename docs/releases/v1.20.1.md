# Zanskar 1.20.1

What the testing board's tickets found, fixed. A WinRM, desktop or application session the
gateway refuses before it starts now says why in the person's tab. A stop by the service
manager ends live sessions with a reason and finishes their recordings. Names given to the
self-signed certificate in the console survive a restart. Several install, upgrade and remove
commands in the docs failed as written. Nothing widens what a session can reach. No migration.
Built with Go 1.27.4.

## Fixed

- **A WinRM, desktop or application session refused before it starts** said only *the session
  ended because of an error*: an account that is not a local administrator on the Windows host,
  a changed RDP certificate, an unreachable host and guacd not configured all looked the same.
  The gateway checks these before the session starts and answered with an HTTP error, which a
  browser cannot read. The tab now shows the reason. The checks still run first, so nothing is
  sent to a listener that fails them.
- **Stopping the gateway** (`systemctl restart`, a package upgrade, `docker compose up -d`) cut
  live sessions without a word, and the next start closed their rows from what the recordings
  held. They now end as a console restart ends them: the person reads *the gateway is
  restarting … reconnect in a moment*, the recording finishes and the row closes as
  `gateway_restart`. New sessions are refused meanwhile. Compose gives the gateway 30 s to stop
  instead of Docker's 10 s.
- **A name added under Regenerate self-signed** was dropped at the next start: the dialog opened
  with an empty Names box, so typing the public address made a certificate for that address
  alone, and the start regenerated it from the configured names. The dialog opens with the
  certificate's names, and a restart or a renewal keeps names given in the console.
- **A MySQL or MariaDB certificate that did not verify** told the client *the gateway log has the
  reason*; the reason was only in the relay's own container log, removed with the session. The
  client now reads that the certificate did not verify against the target's CA bundle and
  address, or that the database could not be reached, still without the host's name.
- **`zanskar audit verify`** on the host names the event where the chain broke, as the console
  and the command line do.
- **Deleting a group** asked to confirm that its policies would be deleted. They are not, since
  1.8.0: the group leaves them. The dialog says so.

## Changed

- **An application's other endpoints** open from the chevron alone; the count beside it is gone.
  The button's name still carries the count.

## Docs

- Backups were written to `/secure/...`, which a clean host lacks and the service user cannot
  write; they go to `/var/lib/zanskar/`, then off the host.
- Helm: the secret is created in the `zanskar` namespace, the admin command names
  `deploy/zanskar-zanskar`, and kind, k3d and minikube need `ReadWriteOnce` for the recordings
  claim.
- Opening 80 and 443 with firewalld or ufw; Caddy is not packaged on Ubuntu 22.04 or Debian 11;
  the Compose volume is `deploy_zanskar_data`; removal names the guacd container and the pulled
  images; first sign-in can register a security key.
- Directory group mappings take a full DN; *Test connection* tests the saved provider; a renewed
  RDP certificate is accepted on the target rather than by probing again.

## Upgrading from 1.20.0

Install the new package, or set `ZANSKAR_VERSION=1.20.1`, and restart. No migration runs. On
Compose, pull the new `deploy/docker-compose.yml` for the 30 s stop grace. The restart that
installs this version is the last one that cuts live sessions without a word.
