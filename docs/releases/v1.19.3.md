# Zanskar 1.19.3

What the live 1.19.2 gateway showed, fixed. An autoscaling instance's host key, pinned when it was
first seen, is now checked against the instance's console output on instance types that keep no
"latest" console: the log line 1.19.2 added named the cause on both of the owner's instances. An
application's other endpoints open in a row of their own beneath it in the Applications list, as a
policy's grants do. An application whose Blocked list is long opens wide enough to show it whole.
Nothing widens what a session can reach. No migration. Built with Go 1.27.4.

## Fixed

- **Autoscaling host keys pinned on first sight were never checked on some instance types.** The
  gateway asked AWS for the instance's latest console output, which those types do not keep: every
  read answered `UnsupportedOperation`, and the key stayed *Pinned when first seen*. The gateway
  now asks again for the output kept from the instance's boot, where cloud-init prints the key
  fingerprints. Any other refusal is not retried.
- **An application's Blocked list** no longer needs a sideways scroll to reach *Allow*: an
  application with one opens 900 px wide, and the page a request came from reads on one line, a
  long one cut short and whole on hover (it broke mid-name, "en.wikipedia.o/rg").
- **Desktops (RDP, VNC)** in Settings carries no description; 1.19.2's "guacd's address." read
  wrong above an on/off switch.

## Changed

- **An application's other endpoints** open beneath it in a row of their own, behind the same
  chevron and count a policy's grants use (*› +2*), name then address with the addresses lined up.
  The application's own row keeps its height, and the address stays selectable. It was a bordered
  "+2 ▾" pill that opened inside the address cell and pushed the row's other cells down.

## Upgrading from 1.19.2

Install the new package, or set `ZANSKAR_VERSION=1.19.3`, and restart. No migration runs. Within
five minutes of the restart the gateway reads each autoscaling instance's console again; an
instance whose image prints its host key fingerprints then reads *Pinned; matches the instance's
console output*. One that still reads *Pinned when first seen* half an hour later has a reason in
the journal: `journalctl -u zanskar | grep 'pinned on first use'`.
