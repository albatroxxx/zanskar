# Zanskar 1.15.0

What a walk through a live gateway found, fixed, and twelve things it suggested, built.
Approvals and outages reach people by webhook or email; a policy's audience is reviewed on the
record; a terminal session can wait for a second person to watch; a command can be found across
every recording; the configuration goes to git as a file. Sessions check the host answers before
they start, say why they failed, and keep no recording of a blank screen; the disk cannot fill
under a session. Built with Go 1.27.3.

## Added

- **Notifications** (ADR 0039). *Settings › Notifications*: a signed webhook (Slack's and
  Mattermost's incoming webhooks show it as it is) or email over SMTP, each told the events it asks
  for: access requested; approved, denied or revoked; a session waiting for a watcher; a session
  ended by an administrator; a sign-in provider failing its sync; a recording lost; new sessions
  refused for a full disk. Channels follow the audit log from their own checkpoint, so nothing is
  lost across a restart or sent twice; a new channel hears what happens from then on. Each message
  links to the page that acts on it; there is no approve-by-link. Secrets (the webhook address, its
  signing key, the SMTP password) are sealed; webhooks are https only, follow no redirect and never
  reach loopback or link-local addresses. *Test* sends one now.
- **Access reviews** (ADR 0040). Each policy has *Review*: every subject, the people a group brings,
  and when each last used the policy, flagging the unused. Remove who no longer needs it, add a
  note, and complete: the removals take effect as an edit would, the policy is stamped reviewed, and
  one `policy.review` event records who was kept, who removed and why. A review older than a quarter
  is due, a dot on the button.
- **Find a command across recordings** (ADR 0041). *Recordings › Find a command*: "systemctl stop"
  across every terminal recording still kept, case-insensitive; each hit opens the recording at that
  command. Command lines are indexed in the background, older recordings once; hidden input is never
  stored; retention deletes the index with the file. Every search is audited with its term.
- **Four eyes** (ADR 0042). A host or autoscaling grant can ask for a second person watching. A
  terminal session it admits waits, saying so, until an administrator or auditor other than its
  owner watches it, and ends after 5 minutes without one; a desktop, database or application session
  under such a grant is refused rather than run unwatched.
- **The configuration as a file** (ADR 0043). *Settings › Configuration file*: export groups, hosts,
  databases, applications and policies as YAML, by name, without secrets; import one with a plan
  first (create, update, unchanged, and anything missing), then *Apply*. Every change goes through
  the API as the importing administrator, with the same checks and audit as a change by hand.
- **Ask for more time inside a session.** A terminal or desktop on a just-in-time grant shows
  *access ends in N min* from 15 minutes before the end, and *Ask for more time* sends the extension
  request without leaving the session.
- **Activity**, in the access portal: a person's own sign-ins (failed ones too, and from where),
  sessions and requests, and what was done to their account, by whom.
- **CSV and saved views** on Sessions and Events: *CSV* downloads every page the filter matches
  (formula-like values written as text, every export audited); *Save view* keeps a filter by name in
  the browser.
- **Security contact.** *Settings › Sign-in › Security contact* publishes
  `/.well-known/security.txt` (RFC 9116) with the operator's address; empty, the file is not found.

## Changed

- **Connect checks the host answers first.** A host that refuses, does not answer within 4 seconds,
  or has no route is refused at Connect in those words; no session and no recording start. The check
  runs after the policy, and dials only what the address rules allow.
- **No room, no session.** While a volume holding the database or the recordings is 95% used, new
  sessions are refused (507 `disk_full`), saying which disk; running ones go on. The dashboard's disk
  gauge warns from 80% and says when sessions are refused.
- **A failed session says why**: under its reason, on Sessions, My sessions, Recordings and the
  player, what the gateway told the person or what the target said (`end_detail`).
- **A desktop that drew nothing keeps no recording**: its file is deleted and its row marked
  discarded, so its events still resolve while the lists leave it out.
- **A provider that does not answer says so.** Its row reads *Sync failed* with the reason in red and
  *Enabled · not answering*; the dashboard opens with a notice; after a failed single sign-on the
  sign-in page says single sign-on is not answering and a password account still works.
- **Failed actions (24h)**, formerly *Failures*, on both dashboards: amber when not zero, and says
  what most were ("mostly provider syncs (19)").
- **Recordings say when they go**: a *Kept until* column, the retention sweeper's own rule.
- **Paths outside the console are not found** (404), where every path answered with the app;
  `/robots.txt` keeps crawlers out.
- **Policies flag a grant that opens nothing**, such as an autoscaling grant by tag with no group
  enrolled.
- Settings' section index stays at the top while it scrolls; page actions sit on the title's row; a
  protocol a target does not offer is a quiet dash, not a disabled button; untagged reads as a dash;
  *Loading…* appears only when a load is slow; an unknown console address says *Not found*; *Review*
  everywhere for a recording; "an HTTP session"; "1 day"; the Events filter lists *policy* once.

## Fixed

- An RDP host that was down answered "the target's certificate does not match the pinned
  fingerprint"; it is `target_unavailable`, and no mismatch is audited.

## Upgrading from 1.14.0

Install the new package, or set `ZANSKAR_VERSION=1.15.0`, and restart. Migrations 0041 to 0044
add columns and two tables and run in moments; the command indexer then reads existing terminal
recordings in the background, 25 every 30 seconds. In the API: `/connect` can answer `409
target_unreachable`, `422 address_forbidden`, `507 disk_full` and `409 watcher_unavailable`; a
session can end `no_watcher`; paths outside the console answer 404. The browser image's contents are
unchanged from 1.14.0; the gateway still fetches the 1.15.0 tag in the background.
