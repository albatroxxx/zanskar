# Zanskar 1.19.2

The console says less. Lines that repeated a heading, told people what a control already says, or
narrated what happens next are gone from its pages and dialogs; a line that carried a consequence
keeps that clause and no more. An application's other endpoints open in its row of the
Applications list, an application's Blocked list is no longer cut off, Recording retention saves
like every other setting, and an identity provider's Delete sits where a host's does. When an
autoscaling instance's host key stays pinned on first sight, the gateway's log now says why.
Nothing widens what a session can reach. No migration. Built with Go 1.27.4.

## Changed

- **The console stops explaining itself.** The session-expired dialog is its title and its
  button; "You have been signed out" and "Signing in again brings you back to this page" are
  gone. So are, among others: the instruction lines above the sign-in steps (the code field now
  reads *Authenticator or recovery code*), "A password account still works" under a provider that
  is not answering, the leads of Activity and Access review, "Ask an administrator for access"
  under an empty list, the restart banner's account of what systemd does, the explanations on the
  watch page's end dialogs, the console command line's "Enter one; it runs again", "is audited"
  notes, tooltips that described what a button does, and setting descriptions that repeated the
  setting's name. A warning keeps its consequence in a clause: "Zanskar cannot
  start it again" before a power-off, "Replaces the trusted key" when a host key changed.
- **An application's other endpoints** open in its row of the Applications list: "+2 ▾" lists each
  endpoint's name and address under the upstream (it was a hover title).
- **Recording retention** has Save and Discard that wake only on a change, says *Saved.* and
  *Changed* with the date beside them, as every other setting does, and its number boxes are the
  size of a number.
- **Settings' boxes and menus** have the console's field border; *Log level* was the browser's
  bare menu.
- **An identity provider's Delete** sits alone at the bottom right of its dialog, as a host's does,
  away from Save; it was at the bottom left beside *Test connection*.

## Added

- **Why a host key stays pinned on first sight.** The gateway logs, once per autoscaling instance,
  why its console output did not settle the key: `console host keys unreadable` (a warning: the
  role may not call `ec2:GetConsoleOutput`, or the read timed out) or `console listed no host key
  the gateway can read` (after the sixth read, half an hour in). The troubleshooting page lists
  both and what to do.

## Fixed

- **An application's Blocked list was cut off** inside its dialog: the reason and the *Allow*
  buttons ran past the edge, and addresses wrapped every few letters. It is a section of its own
  across the dialog's width and scrolls sideways when it must.

## Upgrading from 1.19.1

Install the new package, or set `ZANSKAR_VERSION=1.19.2`, and restart. No migration runs. If an
autoscaling instance still reads *Pinned when first seen* half an hour after the restart, the
journal says why: `journalctl -u zanskar | grep 'pinned on first use'`.
