# Zanskar 1.18.5

What upgrading a live gateway to 1.18.4 and testing it found, fixed: a long search no longer fails,
names cannot hide what they are, the update dialog shows every stage it goes through, every page
names its tab, the log keeps what matters, and the dashboard's image size is right soon after an
update. Nothing widens what a session can reach. No migration. Built with Go 1.27.3.

## Fixed

- **A long search no longer fails.** A query of 2000 words on the Users search answered `500`: each
  word adds placeholders to the statement until the database refuses it. A search now looks at the
  first 8 words, each cut to 64 characters. This was a regression in 1.18.4.
- **A name cannot hide what it is.** A group could be named with a right-to-left override (shown
  as `qa-bidiexe.txt`), a zero-width space (a twin of another name), a newline, a bell, or nothing
  visible at all (a blank row). Names of groups, policies, hosts, databases, applications,
  credentials and identity providers, and an account's display name, now refuse control characters,
  text-direction overrides and isolates, the zero-width space, the word joiner, the byte-order mark,
  the soft hyphen and invisible operators, and a name with nothing to see in it. The joiners that
  Persian, Indic scripts and emoji need, and the left-to-right and right-to-left marks, are kept.
  Descriptions may have line breaks. Names already stored are left as they are.
- **Every page names its tab.** Each tab and each entry in the browser's history read just
  "Zanskar"; they now read "Users & groups · Zanskar" and the like.
- **The update dialog shows its stages.** It follows draining, installing, restarting and back,
  but asked every two seconds and, on the first answer from the new process, swapped the list for
  the green tick. An update takes about seven seconds, so *Restarting* and *Back on* were never
  seen ticked and most of the installer's messages went by unseen. The list now stays, every stage
  ticked, with the installer's messages the view caught under *Installing*; and it asks every half
  second while the installer works and the gateway restarts.
- **The dashboard's image size is right after an update.** *Container images* read 0 B for six
  minutes after an update that had pulled them in thirty seconds, because the first reading ran as
  the gateway started, before the pull ended, and was kept five minutes. A reading of nothing is
  tried again after twenty seconds.

## Changed

- **The log keeps what matters.** Each console page view wrote about eight request lines at info
  (who is signed in, the update check, the host, the command line, pending requests, metrics), which
  filled the 2000-line view within minutes and pushed an update's restart out of it. A served read
  of those is now at debug; a change, a failure and anything a person asked for is still at info.
- **A gateway behind a proxy no longer warns at every start.** With the proxy mode set and the
  proxy trusted to terminate TLS (`ZANSKAR_TRUST_PROXY_TLS`), "listening without TLS" is logged at
  info. Without those it is still a warning.
- **Validation messages lose their package prefix.** "group: invalid input: name must be 1-64
  characters" reads "name must be 1-64 characters", for groups, policies and identity providers.

## For contributors

- `internal/textsafe` is the name check, `Name` for a single line and `Text` for free text. Its code
  points are written as numbers, because an invisible character in its own source would be what it
  keeps out.
- `server.quietPaths` lists the console's shell reads; only a served `GET` is quiet.
- Not changed, noted for the next batch: the audit log records an update's request but nothing when
  the gateway comes back on the new version; the `Cross-Origin-Opener-Policy` header is not sent.

## Upgrading from 1.18.4

Install the new package, or set `ZANSKAR_VERSION=1.18.5`, and restart. No migration runs.

Names that already hold such characters keep working and are not rewritten; saving that group,
policy, host or the like again is refused until its name is made plain. In the API, `POST` and `PUT` of a group, policy, host, database,
application, credential, identity provider or user answer `400` for a name with one of those
characters. The browser image's contents are unchanged from 1.18.4; on a host with an application
enrolled, the gateway still fetches the 1.18.5 tag in the background.
