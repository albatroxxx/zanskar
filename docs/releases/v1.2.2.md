# Zanskar 1.2.2

A fix release on top of 1.2.1. Moving a target no longer looks like an attack, WinRM
sessions on Windows autoscaling groups can fail over again, recordings waiting to upload to
S3 cannot be swapped by another user on the machine, and the console reads in plain words
throughout. Behind it, four in five lines of the gateway are now exercised by tests.

## Changes

**Moving a target starts its trust afresh**
- Saving a target with a new address now clears its trusted SSH host key and its pinned RDP
  and WinRM certificates, as the API documentation always said it would. A new address may
  be a different machine, so probe it and trust it again.
- Before, the old key stayed trusted. The next connection was refused as a *host key
  mismatch*, audited like an attack, when an administrator had only moved the target.
- The console warns under the address field before you save, and the audit event says the
  trust was reset.

**WinRM sessions on autoscaling instances can fail over again**
- A WinRM session never told the browser its session id, so when its instance was lost the
  *move to another instance* dialog did not appear. SSH sessions were not affected.

**Recordings waiting to upload to S3 are kept private**
- With S3 storage, a recording in progress waits in `/tmp/zanskar-spool` unless
  `ZANSKAR_RECORDINGS_SPOOL_DIR` says otherwise. On a machine shared with other users, one of
  them could create that folder first and replace a recording before it was uploaded.
- The gateway now refuses a spool folder it does not own, or that others can write to, and
  says which setting to change. The package's service and the containers were never
  exposed: they have a private `/tmp`.

**The console in plain words**
- Access requests read as sentences in the Events page: *approved bob's request for SSH
  access to web-1*, not *approved access request d2091e4b*.
- An event whose user has been deleted says *deleted user*, not an id fragment.
- Protocols read as names everywhere: SSH, RDP, VNC, WinRM and *database* (it used to read
  DATABASE and WINRM).
- Dates in an event's details read as dates, not as raw timestamps.

**Smaller fixes**
- The file panel beside terminal and desktop sessions works from the keyboard: folders and
  files are buttons you can Tab to.
- Database names no longer wrap at a hyphen when the endpoint is long, and table borders
  stay straight beside the Edit and Delete buttons.
- Confirming an authenticator that is already confirmed answers *already enrolled* (409),
  not an internal error (500). Nothing could be replaced either way.
- The Helm chart's migration job has memory and CPU limits.

**The API documentation matches the server**
- Six update operations were documented as PATCH but are PUT (users, groups, identity
  providers, targets, access policies, autoscaling groups), and four documented operations
  did not exist. The specification now matches, and a test keeps it that way.
- The response of `POST /connect` is documented as what it is: `ticket`, `expires_at` and
  `ws_path`.

**Tested more thoroughly**
- 80% of the gateway's own code is exercised by tests, up from about two-thirds at 1.2.1
  (counted the same way): whole
  terminal, desktop, WinRM and database sessions; who may open, watch or review them;
  approvals; backup and restore; key rotation; first start with HTTPS. Database sessions run
  for real in Docker in CI. Several of the fixes above were found by these tests.
- The web console has a test runner of its own.

## Upgrading from 1.2.1

Install the new package, or set `ZANSKAR_VERSION=1.2.2`, and restart. No migration runs and
no setting needs to change.

**One behaviour change:** saving a target with a different address now clears its trusted
host key and certificates. Probe it and trust it again before users connect. Renaming a
target, or changing anything other than its address, keeps them.

If you run the gateway by hand (not as the package's service or a container) with S3
recording storage on a machine other people use, set `ZANSKAR_RECORDINGS_SPOOL_DIR` to a
private directory, for example `/var/lib/zanskar/spool`. Otherwise a recording is refused
when the shared default is not safe, with a message saying so.

**API changes:** none to requests. Confirming an already-confirmed authenticator now returns
409 `already_enrolled` instead of 500. A client written from the old specification that sent
PATCH for one of the six updates was already getting a 405; send PUT with the whole object.
