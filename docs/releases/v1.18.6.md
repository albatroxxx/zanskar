# Zanskar 1.18.6

What running a public application on the live 1.18.5 gateway found, fixed: a page that is refused
gets the same blocked page as every other, one visit is one row in the application's Blocked list,
the list is readable, and the Add application dialog stays where it opened. Nothing widens what a
session can reach. No migration. Built with Go 1.27.3.

## Fixed

- **A refused page gets the blocked page.** A page typed at a private address was answered with the
  bare text `Zanskar: private`, where a public address that is not one of the application's
  addresses got the styled *This page is blocked*. Both get the blocked page now; the private one
  adds why ("It is a private address, and the gateway reaches those only when an administrator
  allows them"). A script, an image or a fetch refused is still a bare `403`.
- **One visit is one row in Blocked.** The page and the browser's own request for `/favicon.ico`
  after it were two rows. A favicon request that is not a page is no longer said as a refusal.
- **The Blocked list reads cleanly.** In the application's dialog a host, a kind and a time broke
  in the middle of a word (`:8` over `0`, `docume` over `nt`). They stay on one line each; only the
  page that asked may break.
- **A page nobody can allow says so.** The mark for a page someone tried to open at a public
  address that is not an endpoint read *page*. It reads *not an endpoint*; its tip still says an
  endpoint would allow it.
- **Add application stays put.** The dialog was centred, so when the CA bundle field appeared under
  an `https` upstream it moved up under the pointer and a click aimed at *Add endpoint* missed. The
  dialog is anchored at the top.

## For contributors

- `Modal` takes `anchored` for a dialog whose form grows; every short dialog stays centred.
- `apprelay.refusedNote` words why a refused destination is refused; `isFavicon` is the one request
  a browser makes unprompted.
- Not changed: the session header's clock and the ended dialog differ by a few seconds, because the
  header is read a moment before the click.

## Upgrading from 1.18.5

Install the new package, or set `ZANSKAR_VERSION=1.18.6`, and restart. No migration runs. The
browser image's contents are unchanged from 1.18.5; on a host with an application enrolled, the
gateway still fetches the 1.18.6 tag in the background.
