# Zanskar 1.17.0

**An isolated application's pages now load what they depend on from any public address, so every
application already enrolled reaches more than it did: read *Upgrading* before you upgrade.** An
application came up unstyled when its pages fetched stylesheets, scripts, fonts, images or API
calls from a CDN or another host, because the session's relay let only the listed origins
through; now those dependencies load, while a tab, a link, a frame or the address bar still open
pages at the approved origins alone. The dashboard holds four tiles a section and no longer offers
a move to S3. Built with Go 1.27.3.

## Added

- **Dependencies of an application** (ADR 0037, amended 2026-11-03). Chromium's URL policy only
  ever governed navigation; it was the session's relay that refused a page's sub-resources. The
  relay now lets them out, under the application's new setting *Dependencies*:
  - *Any public address* (the default): a page's scripts, styles, fonts, images, API calls and
    WebSockets reach any host on port 80 or 443 whose every address is public. The relay resolves
    the name itself, checks every answer and dials the one it checked, never the name again.
    Loopback, link-local (the cloud metadata services), private ranges, unique local, shared
    address space, multicast, the documentation and benchmarking ranges and the IPv6 ranges that
    carry an IPv4 address inside them are refused, with the reason in the relay's debug log. The
    browser's own service hosts (`accounts.google.com`, `update.googleapis.com`,
    `clients*.google.com`) stay refused, as they were.
  - *Its origins only*: the upstream and the endpoints, as every session was before.

  Opening a page is held to the origins either way: the address bar, a link, a new tab or a frame
  to anywhere else shows Chromium's own *This page is blocked*. A dependency on a private address,
  on another port, or shown in a frame is listed as an endpoint, as before. Choosing *Its origins
  only* for an application ends its open sessions, as removing an endpoint does. In the API,
  `app_dependencies` (`public` or `origins`) on a target; in the configuration file and the
  Terraform provider likewise; the session's start event says which the session ran with.
- **The relay logs at the gateway's level.** With `ZANSKAR_LOG_LEVEL=debug`, an application
  session's relay says what each request asked for and what it decided, so an operator can see
  what a page fetches and why something was refused.

## Changed

- **Dashboard, four tiles a section.** *Needs attention* held six tiles and *Activity* three,
  which read as ragged rows. Each section now holds four: the day's failed sign-ins and refused
  connections sit under *Activity*; the grants running now join the *Pending approvals* tile
  (*oldest waiting 2 hours · 3 granted, 1 ending within the hour*; both open Approvals); the
  *Sign-in providers failing* tile stays, at zero, with no provider configured. Rows are four or
  two tiles wide at every window width, never three and one.
- **Nothing about S3 on the dashboard.** A recordings disk that fills still warns; the offer to
  record to a bucket, and the move of local recordings into one, are on *Settings › Recording
  storage* alone.
- **No search from the address bar** in an application session: search and its suggestions are
  off by policy, so what a person types is not sent to a search engine as they type.

## Upgrading from 1.16.0

Install the new package, or set `ZANSKAR_VERSION=1.17.0`, and restart. Migration 0048 adds one
column to `targets` and runs in moments.

**Every application already enrolled takes *Dependencies: Any public address* when the gateway
restarts.** From then, an application session's pages can fetch from any public address on port
80 or 443, which they could not before. Where a session must stay within the application's own
addresses, open the application in *Applications* and choose *Dependencies: Its origins only*
before people use it; a session open at the time ends. Nothing changes for what a person can open
in a tab, for hosts or for databases.

The relay is the gateway's own image, so this release needs no new browser image; a browser image
pinned from before works as it did.
