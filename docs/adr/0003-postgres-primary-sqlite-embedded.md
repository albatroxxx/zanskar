# 0003. PostgreSQL primary, SQLite embedded

Date: 2026-09-20

## Status

Accepted

## Context

Production deployments need a database that supports multiple gateway replicas, backups, and
row-level concurrency. Evaluations and small teams want to run one binary with no external
service. Supporting two engines has a cost: every query must work on both.

Alternatives considered:

- **PostgreSQL only.** Simplest for us, but the first-run experience requires a database server,
  which kills adoption for an open-source tool.
- **SQLite only.** Cannot support horizontal scaling or managed backups in the way enterprises expect.
- **An abstraction layer or ORM.** Hides the differences but generates SQL we do not control, which
  makes security review harder.

## Decision

PostgreSQL is the primary, recommended database. SQLite, through a pure-Go driver, is supported
for single-node deployments and development. Both are accessed through `database/sql` with
sqlc-generated, parameterized queries.

To keep the two in lockstep:

- SQL is written in the portable subset: no arrays, no JSONB operators, no `RETURNING` beyond
  what both support, no engine-specific functions.
- Primary keys are UUIDs stored as `TEXT`, generated by the application.
- Timestamps are generated by the application and stored as RFC 3339 UTC strings in `TEXT`
  columns, so that ordering and comparison behave identically on both engines.
- JSON documents are stored as `TEXT` and parsed by the application.
- There is one migration set per driver under `migrations/postgres` and `migrations/sqlite`.
  Files must have the same names in both directories. CI fails if the sets differ.
- The test suite runs every store test against both engines.

## Consequences

- We give up some PostgreSQL features (native UUID, JSONB indexing, partial indexes in a few
  cases). For the data volumes of an access gateway this is acceptable.
- Every migration is written twice. The CI check makes drift visible immediately.
- Operators can start with SQLite and migrate to PostgreSQL with a documented export and import.
- Application-generated timestamps mean clock discipline on gateway hosts matters. NTP is a
  deployment requirement.
